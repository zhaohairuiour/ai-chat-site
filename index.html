02 终端

逐字竖排的乱码，是怎么被拆掉的

openclaw doctor 在 xterm-256color 下输出 SGR 颜色与光标定位序列。 WebView 桥接只有行模型，解释不了的序列漏到前端，ESC 字节一丢，剩下的 [90m 就被当成普通字符逐个换行。

  1. 01

    让 CLI 退化为纯文本

    识别 openclaw 类命令，注入 TERM=dumb、NO_COLOR=1、FORCE_COLOR=0、CI=1，并前置 --no-color。其他命令仍保留 256 色。

  2. 02

    按完整字符解码

    4096 字节读缓冲会在多字节字符中间切断。新增尾部不完整序列检测，把残缺字节留到下一块，EOF 再做兜底解码。

  3. 03

    兜底剥离残留序列

    CSI 状态机跨块保存状态；emitBuffer 输出前再剥一层裸 CSI / OSC / 括号粘贴 / 光标序列与 C0 控制字节，前端 stripTermAnsi 做同套正则的二次清洗。

为什么不是「换个字体」

乱码不是字体缺字，而是控制序列被拆散后的语义丢失。修的是解码链路，不是渲染样式。

    07 问答
    
      
    安装之前，你可能想问
    
    
    

    
    
      
    
        
          覆盖安装还是卸载重装？
          
        
        
    
          
    覆盖安装即可。所有 Release 使用同一张 Debug 证书签名，证书 SHA-256 为 79186029…d9c5，升级不会清空本地会话与文件。
    
        
    
      
    
      
    
        
          包里的模型 Key 是空的，还能用吗？
          
        
        
    
          
    公开仓库与附件不含任何明文密钥，直连在线模型会返回 401，这是预期行为。需要填入自己的 Key，后端通过环境变量注入，前端本地核心的 Key 常量留空待填。
    
        
    
      
    
      
    
        
          终端需要 Root 吗？
          
        
        
    
          
    不需要。Termux bootstrap 解包到应用私有目录，targetSdk=24 不受 W^X 限制，直接 exec PREFIX/bin/bash 即可，权限边界仍限制在应用沙箱内。
    
        
    
      
    
      
    
        
          支持哪些 Android 版本？
          
        
        
    
          
    minSdk 24，即 Android 7.0 及以上；原生运行时按 arm64 打包，首次启动会解压约 46 MB 的 Node 二进制。
    
        
    
      
    
      
    
        
          镜像都挂了，更新还能成吗？
          
        
        
    
          
    清单与 APK 下载各有三级回退：ghproxy.net → gh-proxy.com → 直连。本站下载只提供前两个镜像，不暴露 GitHub 直链。全部失败时只提示「更新检查失败」，不影响应用正常使用。
    
        
    
      
    
      
    
        
          为什么安装包有 265 MB？
          
        
        
    
          
    包里塞了完整的 Termux bootstrap、Node 运行时和 OpenClaw 依赖树，换来的是首次启动无需联网下载，断网也能开终端。
